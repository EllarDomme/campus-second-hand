## 二、JDK 版本：统一用 JDK 8

- 工程 `pom.xml` 未声明 `java.version`，继承 Spring Boot 2.7.3 的默认值 → **source/target = Java 8**
- **实测结论（已修正）**：用 JDK 17 跑 Maven 构建**也能成功**，产物字节码仍是 Java 8（版本号 52）。
  也就是说「Lombok 1.18.20 在 JDK 17 下必然编译失败」这个说法**不成立**（曾误写于此，已纠正）。
- 但用新 JDK 编译会打印 `源值 8 已过时 / 目标值 8 已过时` 警告；**IDEA 自带编译器**在新 JDK + 旧 Lombok
  的组合下出现过 `java.lang.ExceptionInInitializerError`。
- **结论：统一用 JDK 8**（与课程原始环境一致，警告与工具链差异都消失）。

| 项 | 值 |
|---|---|
| 构建/运行 JDK | `C:\Program Files\Java\jdk1.8.0_202` |
| Maven | `D:\java_web_develop\apache-maven-3.9.4-bin\apache-maven-3.9.4` |
| 本地仓库 | `...\apache-maven-3.9.4\mvn_repo`（由 Maven `conf/settings.xml` 指定） |

注意本机 `JAVA_HOME` 默认指向 JDK 17、PATH 里 `java` 是 8、`javac` 是 17 —— **三处不一致**，
所有构建命令都必须显式指定 JDK 8（`run-dev.ps1` 已处理）。

## 四、启动方式

```powershell
cd E:\DeskTop\campus-second-hand
powershell -ExecutionPolicy Bypass -File .\run-dev.ps1            # 直接启动
powershell -ExecutionPolicy Bypass -File .\run-dev.ps1 -Rebuild   # 先 clean compile 再启动
```

**为什么不用 `mvn spring-boot:run`？**

1. 本机 Maven 本地仓库（`mvn_repo`）对受限环境不可写 → 无法 `mvn install` 反应堆模块；
2. 若从 `campus-server` 目录直接 `spring-boot:run`，Maven 会从仓库取**旧版**
   `campus-common` / `campus-pojo` jar，这两个模块的改动不会生效
   （例如 `MessageConstant` 常量改名会抛 `NoSuchFieldError`）。

`run-dev.ps1` 的做法是把三个模块的 `target/classes` **放在 classpath 最前面**，
保证运行时拿到的一定是最新编译结果；第三方依赖 classpath 缓存在 `.dsh-cp-server.txt`（已 gitignore，会自动重建）。

**IDEA 用户**：直接以 Maven 项目打开，Project SDK 选 JDK 8，运行 `com.campus.CampusApplication` 即可，不受上述限制。

## 七、配套工具

| 工具 | 用途 | 用法 |
|---|---|---|
| `run-dev.ps1` | 一键编译 + 启动（绕过 `spring-boot:run` 的两个坑） | `powershell -ExecutionPolicy Bypass -File .\run-dev.ps1 [-Rebuild]` |
| `tools/check-schema.py` | 建表脚本静态自检（类型/索引/审计字段/外键…） | 见 `docs/01-阶段1-建表规格.md` §六 |
| `tools/smoke-test.ps1` | 接口冒烟测试：确认"该活的活着、该死的死了" | `powershell -ExecutionPolicy Bypass -File .\tools\smoke-test.ps1` |

**推荐工作流**（每完成一个批次/里程碑）：

```
1. 编译        mvn -o clean compile -DskipTests
2. 启动        .\run-dev.ps1
3. 冒烟测试    .\tools\smoke-test.ps1      ← 必须 0 失败
4. git commit  给这一步留还原点
```

冒烟测试的用例清单在 `tools/smoke-test.ps1` 开头的 `$cases` 数组里，
新增接口就往里加一条（含期望状态码），别让回归验证靠记忆。

> 注意脚本执行策略：本机禁止直接运行 `.ps1`，需加 `-ExecutionPolicy Bypass`；
> 后台运行时用 `Set-ExecutionPolicy -Scope Process Bypass` 更省事（不影响系统设置）。
